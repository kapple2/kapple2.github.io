    한글 베이직(KBASIC)이란? (눌러서 펼치기 / 접기)
    무엇인가요
    KBASIC은 애플 II(II+)의 애플소프트 베이직을 한글 낱말(출력, 만약, 반복 …)로 쓸 수 있게 해 주는 부가 프로그램입니다. 한글로 짠 프로그램을 LIST 하면 한글로 보이고, 변수 이름도 한글로 쓸 수 있습니다. 영어 낱말도 그대로 되고 섞어 써도 됩니다.
    진짜 애플 II 에서 쓰는 디스크 이미지(KBASIC.DSK)가 따로 있어서 실제 기계에서 그대로 돌아갑니다. 이 페이지는 설치 없이 브라우저에서 써 보고 시험해 보는 곳입니다. 실제 디스크는 위의 “KBASIC 다운 받기”에서 받으세요.
    어떻게 만들었나요
    새 베이직을 만든 것이 아닙니다. 애플 II 에 들어 있는 애플소프트를 그대로 쓰고, 한글 낱말(키워드)만 더했습니다.
    • 입력: 한글 낱말을 치면 줄을 마칠 때 영어 낱말(출력→PRINT)로 바꿔 애플소프트의 원래 변환기에 넘깁니다. 그래서 프로그램에는 보통의 1바이트 토큰이 들어가고, 한글로 짠 프로그램은 KBASIC 이 없는 애플 II 에서도 그대로 돌아갑니다.
    • LIST: 토큰을 화면에 찍을 때 한글 낱말로 바꿔 보여 줍니다. 저장되는 내용은 그대로입니다.
    • 크기: 약 2.5 KB 짜리 작은 부가 프로그램입니다. 한글 표시와 입력은 K-HANGEUL 한글 드라이버가 하고, KBASIC 은 그 드라이버에 걸어 쓰는 두 개의 작은 훅과, 한글 변수 이름을 위한 아주 작은 패치만 합니다. 애플소프트 ROM 은 고치지 않습니다.
    • DOS: 마찬가지로 DOS 3.3 도 그대로입니다. 한글 DOS 명령 이름(받기, 제거, 기저장 …)과 한글 오류 메시지(?줄없음 오류)은 K-HANGEUL 드라이버가 해 주는 일이고 DOS 자체를 바꾼 것이 아니며, 오류 번호(PEEK(222))와 ONERR 는 그대로입니다.
    이 페이지와 실제 애플 II 의 다른 점
    이 페이지는 애플 II 에뮬레이터가 아닙니다. 애플소프트 프로그램을 자바스크립트로 옮겨 돌리는 해석기(Joshua Bell 의 jsbasic 바탕)이므로 완전히 같지는 않습니다. 다음은 다를 수 있습니다.
    • 기계어와 메모리: CALL, USR, & 같은 기계어 호출은 안 됩니다. PEEK/POKE 는 일부 번지만 흉내 내며, 실제 메모리 지도(HIMEM, LOMEM 등)에 기대는 프로그램은 돌지 않습니다.
    • 카세트: STORE, RECALL, SHLOAD 는 안 됩니다.
    • 프로그램 명령: LIST, RUN, DEL, CONT 는 없고 편집기와 실행/정지 단추로 대신합니다. NEW(새로)는 프로그램 안에서 쓰면 편집창을 비우고 멈춥니다.
    • 문법 오류: 실행하기 전에 한꺼번에 찾습니다. 진짜 애플 II 는 그 줄에 닿을 때 알려 줍니다.
    • 한글 모양과 입력: 한글은 시스템 글꼴로 두 칸 폭에 그리므로 K-HANGEUL 글꼴과 모양이 다릅니다. 입력은 컴퓨터의 한글 입력기로 하며, 실제 기계의 Ctrl-K/Ctrl-A 한글 모드와 두벌식 자판 입력과는 다릅니다.
    • 그래픽: 저해상·고해상 1, 2쪽과 도형(그려, 엑스그려)은 되지만, 도형 회전은 90도 단위입니다. 색과 화면 모양이 조금 다를 수 있습니다.
    • 디스크 파일: 파일은 디스크가 아니라 이 브라우저의 저장 공간에 만들어지는 가상 파일입니다. 브라우저 데이터를 지우면 사라집니다. 실제 디스크 이미지는 읽지 못합니다.
    • 속도와 소리: 실행 속도는 실제 기계와 다르고(훨씬 빠를 수 있음), 소리는 벨 소리 정도만 냅니다.
    같은 점: 낱말 표, 한글 오류 메시지, 오류 번호, 40열 애플 II Plus 글자 화면(대문자). 중요한 프로그램은 꼭 실제 디스크나 에뮬레이터에서 한 번 더 확인하세요.

    KBASIC 애플 II 시연 영상 
    AI와 함께 만들기 
     
    이 기능은 AI 모델을 내 컴퓨터의 브라우저에 내려받아 씁니다. 시작하기 전에 읽어 주세요.
    • 내려받기: 아래에서 고른 모델 파일(1~2 GB)을 받습니다. 한 번 받으면 브라우저에 저장되어 다음부터는 다시 받지 않습니다. 무선 데이터로 받지 말고 와이파이를 권장합니다.
    • 어디서 받나: 모델은 Hugging Face(huggingface.co), 프로그램은 jsDelivr(cdn.jsdelivr.net)에서 받습니다. 내가 쓴 글과 만든 프로그램은 내 컴퓨터 안에서만 처리되고 어디로도 보내지 않습니다. 한국어로 쓴 요청은 Chrome 내장 번역기가 내 컴퓨터에서 영어로 바꿔 AI 에게 줍니다(번역 자료는 Chrome 이 처음 한 번 내려받습니다).
    • 필요한 것: WebGPU 가 되는 데스크톱 Chrome 또는 Edge 최신 판, 그래픽 메모리 여유, 디스크 여유. 휴대폰과 오래된 브라우저에서는 안 됩니다.
    • 빠르지 않습니다: 그래픽 장치가 있어도 처음 불러오는 데 몇 분, 답 하나에 수십 초에서 몇 분이 걸릴 수 있습니다(문법 오류를 고치느라 다시 만들면 더 걸립니다). 그동안 컴퓨터가 느려지고 팬이 돌 수 있습니다. 작은 모델일수록 빠릅니다.
    • 믿지 마세요: AI 는 틀린 프로그램을 만들 수 있습니다. 문법은 자동으로 검사하지만 꼭 실행해서 확인하세요. 한국어는 영어보다 서툽니다.
    그래픽 장치를 확인하는 중...
    내가 가진 AI 서버를 씁니다. Ollama, LM Studio 처럼 OpenAI 호환 주소(…/v1)를 주는 서버면 됩니다. 이 컴퓨터가 아니라 다른 컴퓨터(원격)의 주소도 됩니다. 모델은 내려받지 않습니다.
    • 어디로 보내나: 내가 쓴 글과 만든 프로그램이 아래 주소의 서버로 보내집니다. 원격 서버면 네트워크를 지나가고, http 주소는 암호화되지 않습니다. 이 사이트로는 아무것도 보내지 않습니다.
    • Ollama: 주소 http://localhost:11434. 서버를 켤 때 이 페이지의 주소를 허용해야 합니다(OLLAMA_ORIGINS). 다른 컴퓨터에서 접속하게 하려면 OLLAMA_HOST=0.0.0.0 도 필요합니다.
    • LM Studio: 주소 http://localhost:1234. 개발자(Developer) 탭의 서버 설정에서 CORS 허용(Enable CORS)을 켜고, 다른 컴퓨터에서 쓰려면 네트워크에서 서비스(Serve on Local Network)도 켭니다.
    • https 와 http: 이 페이지가 https 로 열려 있으면 브라우저가 http 서버(같은 컴퓨터의 localhost 는 예외)를 막습니다. 원격 서버는 https 로 여세요. 크롬은 처음 연결할 때 "로컬 네트워크 접근" 허용을 물을 수 있습니다.
    • 믿지 마세요: 서버의 모델이 클수록 잘하지만 틀린 프로그램도 만듭니다. 문법은 자동으로 검사하니 꼭 실행해서 확인하세요.
